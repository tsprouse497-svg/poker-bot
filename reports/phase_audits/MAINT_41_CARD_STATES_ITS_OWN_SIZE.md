# MAINT-41 audit packet: a committed record states only its own size

The preflop export's source card stored `size.headroom_bytes`, the 20 MiB `data/artifacts` cap less
the bytes of the whole tree. Any file committed anywhere under `data/artifacts` made the card stale,
and six frozen tests then failed as if the chart did not reproduce from its export. Phase 16
restamped the card to get past it at `7d6866f`, and phase 21's lane did the same twice on 2026-10-04.
This closes `SOLVER-EXPORT-CARD-HEADROOM-COUNTS-THE-WHOLE-ARTIFACT-TREE`.

## Diagnosis

Read in `scripts/convert_preflop_export.py` (`build_source_card` settled `headroom_bytes` over
`ARTIFACTS_DIR.rglob("*")`) and `scripts/extract_gtopen_preflop.py` (`write_card`, same loop).
Reproduced on a `git archive` copy of `553f6f7` outside every worktree: one `{"unrelated": true}` file
under `data/artifacts/postflop/` turned exactly the six named tests red. The same probe showed the
postflop index's own `headroom_bytes` had the same defect: a file under `data/artifacts/preflop/`
reddened `test_the_headroom_the_index_states_is_the_cap_less_the_whole_tree`.

## Survey and decisions

Every committed `.json`/`.yml` under `data/` and `verification/` was scanned for byte, headroom and
tree figures, and every script that walks a tree was read. The per-case table is in the ExecPlan.

- Card `headroom_bytes` and `limit_bytes`: removed. One is about the whole tree, the other is a second
  copy of the cap that `scripts/check_file_sizes.py` owns.
- Card `bytes`, `bytes_per_node`, `bytes_per_expressible_spot`: kept. They describe the export.
- Index `headroom_bytes`: removed. Index schema version 2; the importer refuses the key.
- Index `committed_bytes`: kept. It covers only `data/artifacts/postflop/`, and phase 16's contract
  requires it. A file landing inside that directory still moves it, and phase 21 writes campaign
  records there; filed as `POSTFLOP-INDEX-BYTE-COUNT-MOVES-WITH-EVERY-CAMPAIGN-RECORD`.
- Per-cell and equity-table byte counts: kept, each is its own file's size.
- The postflop betting report's whole-tree lines: kept. A generated report measured live from
  `check_file_sizes`' own cap and regenerated every gate run.
- Cap literals in `solve_postflop_sample.py` and `extract_gtopen_preflop.py` now read
  `check_file_sizes.DIRECTORY_BYTE_LIMITS`; the converter has none.

## What shipped

- Converter and extractor stop writing the two keys and drop them from any card they read back.
- `source_card_errors` refuses either key on a card.
- Solve driver stops writing index headroom and prints it live.
- Card and index regenerated by their scripts. The card lost only the two keys. The index lost one
  line, and its `committed_bytes` dropped by that line's 29 bytes.
- **The chart, its sizing table and the export are byte-identical to `553f6f7`**, by sha256 before
  and after `convert_preflop_export.py`, and confirmed by the reviewer by blob hash.

## The cap is as strict as before

Every cap check is unchanged: `check_file_sizes.py` in the base gate, `total < limit` in
`tests/test_solver_export.py`, `test_the_whole_artifact_tree_is_inside_the_cap`, the cap-value test in
`tests/test_solver_expectations.py`, and the extractor's halt over the cap. Only the two comparisons
against a stored copy went. A new test copies `scripts/`, `src/` and `data/artifacts` to a temp dir,
adds an unrelated file, and shows `convert_preflop_export.py --check` still passes, then pads the
tree to exactly the cap (check passes) and one byte over (check fails naming the total). On the old
code that test fails at the converter check.
