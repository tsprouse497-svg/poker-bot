# Phase 09 judgment calls

These are the choices about what a hardening check is allowed to demand. No test in
this repo settles them, because a check that demands the wrong thing passes just as
green as one that demands the right thing. They are recorded before implementation so
that what the gate enforces is a decision somebody made rather than whatever the first
draft happened to enforce.

Every item carries a reversibility class, which the loop driver reads at stage 2 to
decide whether it must stop for a human.

- `runtime-reversible`: the choice only changes behavior at run time, so a later edit
  changes it. The loop takes the default, proceeds, and reports what it chose.
- `frozen-into-data`: the choice is written into a committed artifact that every later
  measurement then runs against. The loop halts until a human answers.

**All six below are `runtime-reversible`, and that claim is the one a reviewer should
attack first.** This phase commits one new file that looks like data: a facts file
holding numbers other documents quote. The reason it is not frozen is that every fact
declares the code that recomputes it, and the gate recomputes it on every run. A wrong
value cannot survive; only a wrong *definition* can, and a wrong definition turns the
gate red the moment anyone computes the number correctly, which is the opposite of the
frozen failure mode. Nothing later in the repo is measured against this file the way
every phase after 05 is measured against the committed chart.

The counter-argument, stated so it is not buried: the 7-versus-24 all-in count that
motivated this phase was exactly a wrong definition, and it survived three documents
and a green gate for a day. What made it survivable was that nothing recomputed it. A
definition recorded next to the code that computes it, and recomputed every run, is a
different object from a number typed into a sentence.

## 1. Whether the facts file is generated or written by hand

Reversibility: runtime-reversible

A hand-written file of numbers is the bug this phase exists to close, one indirection
further back. The whole class of defect is a number that stayed behind after the thing
it described moved, and a hand-written facts file moves exactly as reliably as the
sentences quoting it, which is to say not at all.

Default: the facts file is generated by `scripts/generate_repo_facts.py`, which imports
the repo and recomputes every value, and it is committed so a reader without a working
environment can still see what the documents are being checked against. Regenerating it
is a gate command, so a stale committed copy fails the gate the same way a stale
generated doc already does.

If wrong: the file is 30 lines of derived numbers and deleting it costs nothing but the
checks built on it.

Options: generated-and-committed | hand-written-and-reviewed | generated-and-gitignored
Answer: [generated-and-committed]

## 2. How a document declares that it is quoting a fact

Reversibility: runtime-reversible

Three ways to connect a sentence to a number.

Scan every markdown file for every number and try to work out which fact it is. This
cannot work: most numbers in this repo are not facts, and a checker that guesses would
either fire constantly or be tuned until it fires never.

Put a marker in the prose next to each number. This works, and it makes the documents
worse to read, and a new sentence quoting the same fact carries no marker and so is not
checked - which is the failure mode this phase is closing, reintroduced inside its own
fix.

Have the fact name the files that quote it. The list is short, it lives with the value
and the code that computes it, and a reviewer reading the diff sees both the number and
everywhere it is claimed.

Default: each fact declares its value, the code that recomputes it, and the files that
quote it. The checker requires every listed file to contain the current value in the
declared form.

If wrong: the coupling is a list in one YAML file and can be replaced without touching
any document.

Options: fact-declares-its-quoting-files | inline-markers-in-prose | scan-all-numbers
Answer: [fact-declares-its-quoting-files]

## 3. What happens when a fact's value legitimately changes

Reversibility: runtime-reversible

Two options, and they differ in who edits the sentence.

The generator could rewrite the documents in place. That keeps the gate green with no
human step, and it is wrong: these numbers sit inside sentences that interpret them.
"499 of 500 settle exactly" and "24 of 499 hands contain an all-in" are claims, not
fields, and a script that swaps the digits while leaving the sentence produces a
confident statement nobody made. This repo has already shipped one sentence whose
number was right and whose meaning was wrong.

Or the gate goes red and names the file, the stale value, and the current one, and a
person edits the sentence.

Default: the gate goes red. The check prints the file, the fact, the value it found,
and the value it expected, so the edit is mechanical even though the judgment is not.

If wrong: it costs a manual edit each time a measurement genuinely moves, which in this
repo is rare and is exactly the moment somebody should be reading the sentence anyway.

Options: red-gate-human-edits | generator-rewrites-documents | warn-only
Answer: [red-gate-human-edits]

## 4. What unit mutation coverage is required over

Reversibility: runtime-reversible

`check_gate_bite` proves that a committed mutation is caught. It cannot prove anything
about a command no mutation points at, and two registered `pytest_*` commands currently
have none, including the one covering the full-table preflop strategy.

Per-module coverage was considered and rejected as unmeasurable in a useful way: a
module can be enormous or trivial, and requiring one mutation per module invites one
trivial mutation per module.

Default: coverage is required per registered `pytest_*` command ID. Every such command
must appear in at least one mutation's `must_fail`. Exemptions live by name in the
checker with the reason in the code, so an exemption appears in a diff.

If wrong: the rule is one function and one list.

Options: per-pytest-command | per-source-module | per-phase
Answer: [per-pytest-command]

## 5. What the new full-table preflop canary is allowed to break

Reversibility: runtime-reversible

The uncovered command is the one guarding the module that decides what the bot opens,
calls, and folds preflop. A canary that deletes a symbol proves the module imports. A
canary that changes which hands the chart plays proves the tests are about poker.

Default: the mutation changes a rule that alters the strategy's own action for hands it
already covers, and it must fail `pytest_full_table_preflop`. A crash-shaped mutation
does not satisfy this criterion even though it would satisfy the checker.

If wrong: the mutation is a `find`/`replace` pair in a committed YAML file.

Options: behavioural-rule | import-or-symbol | either
Answer: [behavioural-rule]

## 6. Whether a completed phase's git tag is required to exist

Reversibility: runtime-reversible

A phase's completion is written in four places: `phase_status.yml`, the ExecPlan's
directory, the audit packet, and the `phase-NN-complete` tag. Only the first two are
currently cross-checked, and a tag is the one a reader outside the repo actually uses.

The complication is that a tag is not a file. A clone that fetched no tags would fail a
check that demands them, and the check would then be about the clone rather than about
the repo.

Default: require the tag when the repository has any tags at all, and when it has none,
skip that check and say in the report that it was skipped and why. A skipped check that
announces itself is honest; one that quietly passes is the thing this phase is about.

If wrong: it is one conditional.

Options: require-when-tags-exist | always-require | never-check
Answer: [require-when-tags-exist]
