Postflop Fallback Report
========================

Fallback: postflop-fallback v1
Composite: composite-preflop-chart-postflop-fallback v1

## What this is, and what it is not

This is a continuity device, not a postflop strategy. There is no postflop chart in this
repo and there will not be one in v1, so a simulated hand that reaches a flop would
otherwise have nothing to ask; this fallback checks whenever checking is free, folds to
a bet, and puts money in on exactly one path - a complete board on which no holding a
villain could possibly have beats or ties hero.

What that makes a hand: against another copy of itself every postflop street checks
through, so a hand is decided preflop by the committed charts and then settled at
showdown. Nothing downstream may read postflop quality into it, because there is no
postflop play here to have quality.

## The enumeration over engine-legal postflop states

Coverage is proved by enumeration, not by sampling. The legal-action sets below were not
written down: each one is what the engine's own `legal_actions` returned for a postflop
seat, swept over every combination of current bet, hero's street bet, and hero's
remaining stack that the engine can be put in. If the engine ever produces a new action
set, this sweep widens on its own rather than missing it.

## Where money goes in: the worked river examples

The river call is the only path in this module that invests, so it is written out as
cards. Hero can see seven of the 52 cards - two in hand and five on a complete board -
which leaves 45 unseen and 990 possible two-card villain holdings. Every one of them is
ranked with the same evaluator that ranks hero's own hand. No hand categories, no table
of nut hands, no sampled subset.

The bar is strict: hero calls only when no holding beats hero and no holding ties hero.
A guaranteed chop pays a full call to win half a pot, and the price at which that is
correct is a number this repo cannot source.

The `hero holds` column is the evaluator's own category name. It has no separate
royal-flush category, so a royal flush reads there as a straight flush.

hero    board               hero holds          beat   tie   verdict
Ac Kc   Qc Jc Tc 2d 3h      straight flush         0     0   calls
Ac 2c   As Ah Ad Kc Kd      four of a kind         0     0   calls
Ad Kd   2d 3d 4d 5h Kc      flush                  1     0   folds
Kd Qh   9c 9d 9h 9s Ac      four of a kind         0   990   folds
2d 7h   Ac Kc Qc Jc Tc      straight flush         0   990   folds

royal flush in hand: Ac Kc on Qc Jc Tc 2d 3h
  Calls, because hero holds a royal flush in clubs; nothing beats a royal flush, and the
  only hand that ties it needs Ac and Kc, both of which hero holds. Of 990 possible
  villain holdings, 0 beat hero and 0 tie hero.

quad aces holding the fourth ace: Ac 2c on As Ah Ad Kc Kd
  Calls, because hero holds four aces with a king; only a straight flush beats quad aces
  and no three board cards share a suit, so no flush exists, and a tie needs the fourth
  ace, which hero holds. Of 990 possible villain holdings, 0 beat hero and 0 tie hero.

nut flush that one straight flush beats: Ad Kd on 2d 3d 4d 5h Kc
  Folds, because hero holds the ace-high flush and no villain flush can match it, but 6d
  5d makes 2d 3d 4d 5d 6d, a six-high straight flush; one holding out of 990 is enough
  to fold. Of 990 possible villain holdings, 1 beat hero and 0 tie hero.

quad nines with the kicker on the board: Kd Qh on 9c 9d 9h 9s Ac
  Folds, because hero's best five cards are the four nines and the ace, all of them on
  the board, so every villain holds the same hand: nothing beats hero and every holding
  chops. Of 990 possible villain holdings, 0 beat hero and 990 tie hero.

royal flush on the board: 2d 7h on Ac Kc Qc Jc Tc
  Folds, because the nuts is the board itself, a royal flush, and hero's two cards are
  irrelevant; hero cannot hold that hand as a two-card holding and neither can any
  villain, so the whole table chops. Of 990 possible villain holdings, 0 beat hero and
  990 tie hero.

The exception is the river only. On the flop and the turn the same claim would have to
mean 'nothing beats me after any runout', which is a far larger enumeration, so a flop
or turn bet always takes the pot from this bot. That gap is recorded in `backlog.yml`
rather than approximated.

## What the composite does over the committed sample hands

Fixture: `data/samples/normalized_hands.json`

One strategy object plays the whole hand: preflop from the committed charts, flop
through river from the fallback. Every recorded action in a hand is a decision point. A
point can only be asked when the hand history records that seat's hole cards, which it
does only for seats that reached showdown, so points belonging to a seat that folded
earlier are skipped rather than guessed at.

These four hands were recorded to exercise the replayer, not to be preflop spots the
six-handed 100bb charts cover, so the chart refuses every one of them. That is the
behavior to want: a refusal carries its own reason code out to the caller instead of
being quietly converted into a check.

  phase02-heads-up-showdown
    preflop seat 0   refused  (preflop-chart:lookup:no-artifact-for-table-size)
    preflop seat 1   refused  (preflop-chart:lookup:no-artifact-for-table-size)
    flop    seat 1   check  (postflop-fallback:check-when-free)
    flop    seat 0   check  (postflop-fallback:check-when-free)

Read the per-hand listing above as the shape of a hand played by this bot: the chart
speaks preflop or declines to, every postflop street checks through, and the hand is
settled at showdown. Nothing bets and nothing raises after the flop.

## Check one number by hand

Postflop decision points across the committed sample hands: 10.

Open `data/samples/normalized_hands.json`. For each hand, go to `streets` and find the
entries named `flop`, `turn` and `river`, ignoring `preflop`. Count the entries in each
one's `actions` list and add them up. The replayer visits exactly one decision point per
recorded action, so that tally is the number above.

  phase02-heads-up-showdown       flop 2, turn 2, river 2                    6
  phase02-three-way-side-pot      flop 0, turn 0, river 0                    0
  phase02-preflop-fold-out        no postflop streets                        0
  phase02-turn-fold-out           flop 2, turn 2                             4
  total                                                                     10

Counting the file by hand gives 10. Driving the same file through the replayer and the
composite reached 10 postflop decision points. The two agree, and the first of them
needed no code at all.

The two `post_blind` entries that open every preflop street are deliberately not in this
count. They are forced posts rather than decisions, and the replayer never offers them
to a strategy.

## The committed decision audit

`reports/active/latest_postflop_decision_audit.jsonl` holds one line per decision in the
Phase 03 record shape, written with the same serializer as the preflop audit, so the
reader that already checks preflop decisions checks these unchanged.

  from the enumeration                                  72
  from the sample hands (postflop only)                  6
  total lines                                           78

Refusals are counted in this report and are deliberately not written to that file. The
record shape does accept a refusal, but a decision audit whose lines are not all
decisions is a file every future reader has to filter before trusting a count, and the
preflop refusals worth auditing are already Phase 05's own evidence.

Every line was constructed through `DecisionAuditRecord`, which is what proves legality:
it rejects an action outside `legal_actions`, an amount above all-in, and an amount
below the minimum raise target. A decision that was not legal could not have been
written to the file.
