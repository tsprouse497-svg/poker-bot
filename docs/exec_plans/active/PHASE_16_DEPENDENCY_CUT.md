# ExecPlan: Cut phase 16's dependency on phase 15

Task: `PHASE_16_DEPENDENCY_CUT`, `contract-update`, on `main` in the primary checkout.
Base commit `9bbdcf4`.

## Objective

Phase 16 is the phase that makes the bot play hands. Today every postflop street checks through, so
the bot answers a preflop question and then runs the hand out; phase 16 is the only declared phase
that changes that. Its contract declared `depends_on: "15"`, so `loop_fleet.py --plan` reported it
held behind a training tool for a human.

Cut the edge, record why, and leave phase 16 startable.

## Outcome

Done. Phase 16 no longer waits on phase 15. `loop_fleet.py --plan` reports it startable once this
lands on `main`, and the edge it now carries - `14` - is the committed chart its flop solve is keyed
against, which is a content dependency rather than a sequence one.

What the review changed, and it is the more useful record. Two of its three blockers were about the
same thing: the graph is written in more places than the contracts, and only the contracts are
checked. `docs/ROADMAP.md` held a hand-typed table row and an ASCII diagram drawing `14 -- 15 -- 16`,
thirteen lines above its own sentence naming the contracts as the single source, and nothing
generates or checks that section - so without the review the repo would have shipped a picture
contradicting the file it cites. Filed as `PHASE-GRAPH-IS-WRITTEN-TWICE-AND-CHECKED-ONCE`.

The third is worth carrying further than this task. My recorded diagnosis said the edge rested on one
roadmap sentence. It did not: the v2 contracts were declared with `depends_on` as a straight chain -
sequence rather than semantics, with nothing reading the field - and a later task that re-derived the
edges recorded 15 and 16 as "already right" without tracing either. So a review did look and affirmed
an edge it had not traced. The lesson is that an edge must carry the reason it exists, not that
someone should check. Filed as `A-DEPENDS-ON-EDGE-INHERITED-FROM-A-CHAIN-IS-NEVER-RE-EXAMINED`.

is still `deferred`. So the `14` edge is met on paper while the specific output 16 needs from it does
not exist yet. That is a real input to 16's contract stage and it is not a reason to hold the lane.
