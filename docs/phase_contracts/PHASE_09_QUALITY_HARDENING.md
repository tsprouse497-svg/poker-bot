# Phase 09: Quality, Drift, Backlog, And Phase-Gate Hardening

## Scope
Every phase before this one added something the repo can do.
This one adds nothing, and instead closes the ways the repo can be wrong while every
check passes.

There are three such ways, and all three have already happened rather than being
imagined here.

A gate command can be decorative. `check_gate_bite` proves a mutation is caught, but
nothing proves a command has any mutation aimed at it, and two registered `pytest_*`
commands have none - including the one that covers the full-table preflop strategy,
the most consequential module in the repo.

A number in a committed document can drift from the data it describes. The Phase 08
audit packet said 7 all-in hands where the sample holds 24, and said 3,056 decision
points where the comparison produces 3,048, and stated a pooled figure under a label
saying it was not pooled. Each survived a green gate, because prose is not checked.

A backlog entry can rot. An item can name a phase that does not exist, an audit packet
can cite an id that was never filed, and an entry can sit as the only record of work
nobody can act on while the evidence that diagnoses it is already in the tree.

It is limited to the work named by this contract and the active ExecPlan.

## Non-goals
- Do not add PokerNow automation.
- Do not add browser or platform observation.
- Do not add runtime solver calls.
- Do not add LLM-backed poker decisions.
- Do not add training UI surfaces.
- Do not change any poker behavior.
  No engine, chart, strategy, simulator, converter, or committed artifact changes in
  this phase. A hardening phase that edits the thing it is measuring cannot be trusted
  to have hardened anything, and every check here must pass against the repo as it
  already is or fail loudly enough to be fixed in its own task.
- Do not weaken an existing check to make a new one pass.
- Do not add a check whose failure a reader cannot act on.
  A check that reports a problem without naming the file, the value, and what it should
  be is a check nobody will keep.

## Acceptance criteria

### Every gate command that claims to prove something is proved to bite
- Every registered `pytest_*` command ID appears in the `must_fail` list of at least one
  committed mutation, and the gate fails when that is not true.
  `check_gate_bite` proves a mutation is noticed; it cannot notice a command no mutation
  points at, and a command with no mutation aimed at it is an assertion that the tests it
  runs are worth something.
- A command that is genuinely exempt is exempt by name in the checker, with the reason
  stated in the code, and the exemption list is part of the diff a reviewer reads.
  Silence is what this criterion exists to remove, so an exemption nobody can see would
  reintroduce it.
- The two commands currently uncovered are covered by mutations that bite, and the
  mutation for the full-table preflop strategy targets a rule that would change which
  hands the chart plays rather than one that would crash.
  A canary that trips on a syntax error proves the module imports, not that the poker is
  checked.

### A number stated in a committed document matches the repo it describes
- A committed facts file records every cross-document number this repo repeats, each
  with the code that recomputes it, and it is regenerated by a command in the gate.
  The number lives in one place and every document quotes that place.
- The gate fails when a document listed for a fact states a value the fact no longer
  has, naming the file, the stale value, and the current one.
  This is the whole point: the three drift defects above were each a number that stayed
  behind after the thing it described moved.
- The check is honest about its reach and says so in its own output: it verifies the
  facts it has been given, and a number nobody registered is a number nobody checks.
  A drift checker that implies it read every sentence is worse than none.

### The backlog is a live work list rather than an archive
- Every item carries a unique id, a status from a closed set, a phase, a title, and a
  reason, and the gate fails on a malformed or duplicated entry.
- Every backlog id cited anywhere in `docs/`, `reports/`, or the contracts resolves to an
  item that exists, and the gate names any citation that does not.
  A packet that files a finding under an id nobody created has recorded nothing.
- Every phase named by an item is a phase in `phase_status.yml` or a declared
  non-phase label, so an item cannot be filed against work that does not exist.

### The phase record agrees with itself
- Every phase marked completed has its `phase-NN-complete` tag, its ExecPlan in
  `docs/exec_plans/completed/`, and an audit packet that exists and names it.
- The gate fails when any of those disagree, naming which phase and which record.
  These are the four places a phase's completion is written down, and until now only two
  of them were cross-checked.

### Reports and gate
- Required command IDs pass through `scripts/run_verify.py`.
- Required reports exist and are fresh for this phase.
- `reports/active/latest_quality_report.txt` states, in plain language, what each check
  covers and what it does not, so a reader can tell the difference between a check that
  passed and a claim that was never checked.
- The phase audit packet includes plain-language pass/fail evidence.
- The judgment calls recorded in
  `reports/phase_audits/decisions/PHASE_09_QUALITY_HARDENING_DECISIONS.md` carry a
  reversibility class before implementation begins, and the audit packet records the
  outcome of each one.
- Any deferred work is recorded in `backlog.yml`.

## Human vetting packet requirements
- Plain-language summary of what changed.
- Pass/fail checklist for a non-coding reviewer.
- Command summary with links to committed reports.
- What each new check covers, and what it deliberately does not.
- The recorded judgment calls and what each one changed.
- Known limitations and deferred items.

## Forbidden shortcuts
- Do not replace deterministic checks with mocked success.
- Do not infer missing strategy, chart, or hand-history behavior.
- Do not exempt a command, a fact, or a backlog item from a check in order to make the
  check pass.
  An exemption is a decision with a reason, recorded where a reviewer reads it, and a
  check whose exemption list grows to fit the repo is measuring nothing.
- Do not register a fact whose value the checker itself supplies.
  A fact recomputed from the document that states it is a mirror, which is the same
  defect this repo already found in its own settlement oracle.
- Do not change this contract during implementation mode.

## Regression expectations
- Previously completed phase gates remain verifiable.
- No poker behavior changes: the engine, replayer, charts, strategies, simulator, and
  committed artifacts are byte-identical at the end of this phase.
- Generated human docs remain current.
- File-size and scope checks continue to pass.
